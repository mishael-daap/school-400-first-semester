## Algorithm Analysis

The major resources considered are **execution time** and **memory space**.

Definition: algorithm analysis is estimating the efficiency of an algorithm.

## Time and Space Complexity

**Time complexity** measures the number of operations performed by an algorithm, and how it grows with input size.

**Space complexity** measures the amount of memory required by an algorithm during execution. It includes memory used for variables and data structures.

Common examples:

- O(1)
- O(n)
- O(log n)
- O(n²)

## Examples of Algorithm Analysis

### Linear Search

Compares all the elements with the target element until the element is found or the list ends.

### Binary Search

Sorts the list first, then compares the target with the middle element and then discards half of the search area.

For large sorted lists, binary search is more efficient.

## Importance of Algorithm Analysis

- Determine how effectively an algorithm uses time and memory.
- Compare algorithms and identify which approach is more efficient.
- Improve program performance, find inefficient operations, and optimise solutions.
- Handle large datasets and predict how an algorithm performs as the input increases.
- Optimise resource usage and reduce unnecessary memory consumption and computation.

## Computational Efficiency

Describes how effectively an algorithm uses available computing resources to solve a problem.

It is influenced by:

- Algorithm design
- Data structures
- Input size
- Time complexity
- Space complexity

## Characteristics of an Efficient Algorithm

- Executes with minimal computational effort.
- Uses memory effectively.
- Maintains good performance as input size increases.
- Produces correct results.

## Time Complexity

Describes how the number of basic operations performed by an algorithm grows as the input size increases.

## Example: Printing the Elements of an Array

Initialize an array of 5 numbers, then use a `for` loop to print out each element.

```java
int[] numbers = {10, 20, 30, 40, 50};

for (int number : numbers) {
    System.out.println(number);
}
```

The loop runs once per element, so for `n` elements it performs `n` print operations. That is **O(n)** time.

## Space Complexity

Describes how much memory an algorithm requires as the input size increases.

It considers:

- The memory required to store the input
- Variables and constants
- Additional data structures
- Temporary memory
- Memory required by recursive function calls

## Example: Summing the Elements of an Array

Initialise `sum` and set it to `0`, then use a `for` loop that keeps incrementing `sum`.

```java
int[] numbers = {10, 20, 30, 40, 50};
int sum = 0;

for (int i = 0; i < numbers.length; i++) {
    sum = sum + numbers[i];
}

System.out.println(sum);
```

Only two extra variables are used — `sum` and the loop counter `i` — no matter how large the input is, so the extra space is **O(1)**.

## Example: Linear Space — O(n)

Create an array with `new int[...]`, then use a `for` loop to fill it.

```java
int n = 5;
int[] numbers = new int[n];

for (int i = 0; i < n; i++) {
    numbers[i] = i * 10;
}
```

The array holds `n` integers, so the memory used grows in step with the input size. That is **O(n)** space.

## Differences: Time Complexity vs Space Complexity

| Time complexity | Space complexity |
| --- | --- |
| Computational operations | Memory operations |
| Execution time growth | Memory usage growth |
| Examines how operations increase with input size | Examines how memory requirements increase with input size |
| Example: O(n) | Example: O(n) |

## Understanding Input Size

Input size is the amount of data an algorithm receives or processes.

It is represented by the variable `n`.

Examples:

- Searching an array
- Sorting a list: `n` represents the number of items to be sorted
- Processing a string: `n` represents the number of characters
- Multiplying two matrices: `n` may represent the dimension of the matrices

## Input Size `n`

| Problem | Natural input size `n` |
| --- | --- |
| Sorting and searching | Number of elements in the array |
| Graph algorithms | Number of vertices and edges |

## Basic Operations in Algorithm Analysis

A basic operation is a fundamental computational action performed by an algorithm.

Basic operations include:

- Assignment operation
- Arithmetic operation
- Comparison operation
- Logical operation
- Array access operation
- Function calls

## Example: Basic Operations in Java

Set `a` to 10 and `b` to 200, sum `a` and `b`, and if the sum is greater than 20, print the sum.

```java
int a = 10;
int b = 200;
int sum = a + b;

if (sum > 20) {
    System.out.println(sum);
}
```

The basic operations in this snippet:

| Line | Basic operation |
| --- | --- |
| `int a = 10;` | Assignment operation |
| `int b = 200;` | Assignment operation |
| `int sum = a + b;` | Arithmetic operation + assignment operation |
| `sum > 20` | Comparison operation |
| `System.out.println(sum);` | Function call |

## Counting Operations in Summing an Array

Pseudocode:

```
SUM(A, n)
1   total ← 0
2   for i ← 1 to n do
3       total ← total + A[i]
4   return total
```

Line and number of executions:

| Line | Statement | Executions |
| --- | --- | --- |
| 1 | `total ← 0` | 1 |
| 2 | `for i ← 1 to n do` | `n + 1` |
| 3 | `total ← total + A[i]` | `n` |
| 4 | `return total` | 1 |

Total operations: `n + 1 + n + 1 + 1 = 2n + 3`, which is **O(n)**.

## Cases in Algorithm Analysis

An algorithm may perform differently depending on the nature or arrangement of its inputs.

The three common cases are:

- Best case analysis
- Average case analysis
- Worst case analysis

These can help us understand an algorithm's performance under different input conditions.

## Best Case Analysis

Examines the minimum number of operations an algorithm performs for an input of a given size.

It represents the most favourable input condition.

Example: linear search.

Find a number in an array with the numbers 10 through 50 counting in tens:

```java
int[] numbers = {10, 20, 30, 40, 50};
int target = 10;
```

Best case: the target is the first element, so linear search finds it after **1 comparison** — **O(1)**.

## Average Case Analysis

Examines the expected number of operations an algorithm performs across possible inputs of a given size.

## Worst Case Analysis

Examines the maximum number of operations an algorithm performs for an input of a given size.

It represents the least favourable input conditions.

Example: linear search, using the same code as the best case example:

```java
int[] numbers = {10, 20, 30, 40, 50};
int target = 50;
```

The worst case occurs when the target is the last element (50), or when the target does not exist in the array. In that case every element is compared, so the worst case is **O(n)**.
