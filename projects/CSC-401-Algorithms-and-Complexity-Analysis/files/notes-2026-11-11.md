## Growth of Running Time: Dominant Terms

Consider two algorithms:

- t₁(n) = 3n + 5
- t₂(n) = n² + 2n + 10

For large values of n, the dominant terms are 3n and n² respectively.

Therefore:

- t₁ grows **linearly**.
- t₂ grows **quadratically**.

| n | t₁(n) = 3n + 5 | t₂(n) = n² + 2n + 10 |
| --- | --- | --- |
| 5 | 20 | 45 |
| 10 | 35 | 130 |
| 20 | 65 | 430 |
| 100 | 305 | 10,210 |
| 1,000 | 3,005 | 1,002,010 |

## Importance of Asymptotic Analysis

- **Compares algorithms:** provides a common basis for comparing different algorithms.
- **Predicts scalability:** helps estimate how algorithms behave when processing large data sets.
- **Identifies efficiency:** shows how quickly computational requirements grow.
- **Supports algorithm selection:** helps programmers choose suitable algorithms for particular problems.
- **Ignores hardware differences:** allows theoretical comparison without depending on a specific computer.
- **Guides optimisation:** helps identify algorithms with inefficient growth rates.

## Three Principles of Asymptotic Analysis

This leads to three important principles.

1. **Ignore constant multiplicative factors when classifying asymptotic growth.**
   If an algorithm takes 5n steps and another takes 100n steps, doubling n roughly doubles the work in each case. The constant depends on the language and compiler being used.

   Formally, f(n) = 5n is O(n) because we can pick a constant c = 5 so that 5n < c·n for all n.

2. **Ignore lower-order terms when a higher-order term dominates.**
   Take f(n) = 3n² + 10n + 50. As n grows, the n² term overwhelms the others.

3. **Retain the dominant term, because it determines the asymptotic growth rate.**
   What remains here, 3n², is the term that controls the growth rate. Combined with rule 1, if we drop the 3 as well, the result is:

   3n² + 10n + 50 = O(n²)

## Asymptotic Notations

- Big O notation — **O**
- Big Omega notation — **Ω**
- Big Theta notation — **Θ**

### Big-O Notation — O

- Describes an asymptotic upper bound on the growth rate of an algorithm's resource requirements.
- In introductory algorithm analysis, it is commonly used to express worst-case time complexity.

**Example:** Consider the function t(n) = 3n + 5. As n becomes large, the constant term becomes less significant. Therefore, t(n) = O(n).

### Big-O: Practical Example

Consider the following Java code:

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}
```

The loop runs `n` times, and the body is a single print, which is constant work. So the total number of operations grows in step with `n`:

t(n) = n × 1 = O(n)

Why that count is right:

- The loop starts at zero.
- It executes once for every value of `i` less than `n`.
- It therefore performs approximately `n` iterations.

### Big-Omega Notation — Ω

- Describes the lower bound of the growth rate of an algorithm's resource requirements.
- It indicates that the algorithm's resource usage grows at least as fast as a particular function, asymptotically.

**Example:** Consider t(n) = 3n + 5. Its asymptotic lower bound is Ω(n).

### Worked Example: Linear Search — Best and Worst Case

```java
public static int search(int[] numbers, int target) {
    for (int i = 0; i < numbers.length; i++) {
        if (numbers[i] == target) {
            return i;
        }
    }
    return -1;
}
```

**Best case:** target at index 0, one comparison, so t(n) = 1 = O(1) = Ω(1) = Θ(1).

**Average case:** target equally likely anywhere, (n + 1) / 2 comparisons, so t(n) = (n + 1) / 2 = O(n) = Ω(n) = Θ(n).

**Worst case:** target last or absent, 2n + 1 operations, so t(n) = 2n + 1 = O(n) = Ω(n) = Θ(n).

### Big-Theta Notation — Θ

- Describes an asymptotically tight bound on the growth rate of an algorithm's resource requirements.
- It means the function grows at the same asymptotic rate as the stated bound, up to constant factors.

**Example:** Consider t(n) = 5n + 10. The dominant term is n. Therefore, Θ(n).
